# 部署说明：GitHub → Cloudflare Workers（自动构建）

最终流程：**改代码 → 推到 GitHub → Cloudflare 自动构建并部署 → 玩家访问新版本**。

整个网站是纯静态的（三个游戏都在浏览器里运行），只用一个 **Cloudflare Workers（仅静态资源）** 项目托管。没有后端，没有数据库，也不需要登录。

| 网址 | 内容 |
| --- | --- |
| `/` | 入口页（三张游戏卡片） |
| `/arena/` | 字形乱斗 1v1 |
| `/soccer/` | 字形足球 4v4 |
| `/basketball/` | 字形篮球 2v2 |
| 其他路径 | 404 页面 |

## 一、仓库里已经准备好的东西

| 文件 | 作用 |
| --- | --- |
| `wrangler.jsonc` | Workers 配置：只托管 `dist/`，`/soccer` 自动补成 `/soccer/`（保留 `?` 后面的参数），找不到的路径返回 404 页 |
| `deploy/_headers` | 构建时复制到 `dist/_headers`：带哈希的 JS/CSS 永久缓存，音效缓存一个月，网页每次都检查新版本 |
| `portal/404.html` | 404 页面 |
| `.node-version` | 构建机用 Node 22 |
| `package.json` | 加入了 `wrangler`（devDependency），以及 `npm run deploy`、`npm run preview:worker`、`npm run audio:compress` 三个命令 |
| `scripts/build-all.mjs` | `npm run build` 一次构建三个游戏和入口页到 `dist/`；会删掉已有 mp3 的 wav，并检查 Cloudflare 的文件大小限制 |

几个关键检查结果：
- **音效：** 已从 wav（141.7 MB）压缩成 mp3（13.2 MB）。原始 wav 留在你电脑上，不进 Git。
- **体积：** 现在一个游戏首次加载的音效大约 4–5 MB（以前约 47 MB）。整个网站 38 MB，最大单个文件 1.4 MB（Cloudflare 限制是单文件 25 MiB、免费版 20,000 个文件）。
- **路径：** 三个游戏都用相对路径（Vite `base: './'`），放在子目录里能正常运行。
- **编码：** 网页以 `text/html; charset=utf-8` 返回，中文、日文、英文、Emoji、颜文字都已测试正常。

## 二、第一次上线（大约 10 分钟）

### 1. 把代码放到 GitHub

本地仓库已经建好并提交（分支 `main`）。

1. 打开 https://github.com/new 新建一个仓库，例如叫 `wenzibattle`，选 **Private**。**不要**勾选 README / .gitignore / License。
2. 在项目文件夹（`D:\GameDevelopmentRandom`）运行下面两条命令（把 `你的用户名` 换掉）：

```bash
git remote add origin https://github.com/AY-gift/wenzibattle.git
```

```bash
git push -u origin main
```

第一次推送时，Windows 会弹出 GitHub 登录窗口，在浏览器里授权即可。

### 2. 在 Cloudflare 连接仓库

1. 登录 https://dash.cloudflare.com → 左侧 **Workers 和 Pages（Workers & Pages）** → **创建（Create）**。
2. 选 **导入存储库（Import a repository）** → 连接 GitHub（第一次会让你在 GitHub 授权 Cloudflare 访问这个仓库）→ 选 `wenzibattle`。
3. 设置：
   - **项目名称：** `wenzibattle`（必须和 `wrangler.jsonc` 里的 `name` 一样）
   - **生产分支：** `main`
   - **构建命令（Build command）：** `npm run build`
   - **部署命令（Deploy command）：** `npx wrangler deploy`
   - **根目录（Root directory）：** `/`（保持默认）
4. 点 **部署（Deploy）**。Cloudflare 会自动 `npm install`，然后构建并上线。第一次大约 2–4 分钟。
5. 完成后会给你一个网址，例如 `https://wenzibattle.hershel54.workers.dev/`。

### 3. 设置正式网址（让 SNS 分享卡片带图片）

X、LINE、Discord 的链接预览需要**完整网址**的 OG 图片，所以要告诉构建正式网址：

1. Cloudflare → 这个 Worker → **设置（Settings）** → **构建（Build）** → **变量和机密（Variables and secrets，构建用）** → 添加：
   - 名称：`SITE_URL`
   - 值：`https://wenzibattle.hershel54.workers.dev/`（结尾要有 `/`；以后换成自定义域名就改这里）
2. 回到 **部署（Deployments）** → 对最新一次点 **重试部署（Retry deployment）**（或随便推一次代码）。

不设置也能玩，只是分享出去的链接预览可能没有图片。

### 4.（可选）自定义域名

Worker → **设置（Settings）** → **域和路由（Domains & Routes）** → **添加（Add）** → **自定义域（Custom domain）**，输入你在 Cloudflare 上的域名，例如 `play.example.com`。然后把第 3 步的 `SITE_URL` 改成 `https://play.example.com/`，再重新部署一次。

## 三、以后怎么更新

- 改完代码后提交并推送：`git push`。
- 推送到 `main` 后，Cloudflare 会自动构建并上线，在 **部署（Deployments）** 里能看到进度和日志。
- 构建失败时，线上保持上一个版本，不会变成坏页面。

**加了新的 wav 音效时：** 先把 wav 放进对应游戏的 `public/audio/`，然后在项目根目录依次运行：

```bash
npm run audio:compress
```

```bash
npm run audio:index -w @glyph/soccer
```

（`soccer` 换成对应的游戏：`arena` / `soccer` / `basketball`）。最后把生成的 `.mp3` 和 `available.json` 一起提交。wav 不会被提交。

## 四、本地检查（可选）

```bash
npm test
```

```bash
npm run build
```

```bash
npm run preview:worker
```

最后一条会用和 Cloudflare 一样的方式在 http://localhost:8787 提供 `dist/`，可以检查 `/`、`/arena/`、`/soccer/`、`/basketball/`、刷新、互相切换、分享链接。

如果想跳过 GitHub、从本机直接部署：先运行 `npx wrangler login` 在浏览器里授权，再运行 `npm run deploy`。

## 五、关于 Supabase

**现在不需要。** 游戏没有账号、排行榜或服务器存档：分享链接只携带分享者选择分享的内容，战报也只在链接里，不存在任何服务器上。

以后如果要做排行榜、云端保存、每日挑战，再接入 Supabase。到时候：
- 前端只能放 **anon key**（配合 RLS 规则），**service role key 绝对不能放进前端或 Git**；
- 需要的密钥放在 Cloudflare 的「变量和机密」里。

## 六、安全

- 仓库里没有任何密钥（已扫描）。`.env`、`.dev.vars`、`.wrangler/` 都在 `.gitignore` 里。
- 可选的统计地址 `VITE_ANALYTICS_URL` 只是一个公开的接收地址，不是密钥；不设置就不发送。
- 玩家输入只放在网址参数里，网页用 `textContent` 显示，不会被当作 HTML 执行。
