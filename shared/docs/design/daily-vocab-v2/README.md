## 目的与限制

- 重点选取真实玩家可能自发输入的**单字、日常用语、网络口头禅、工作上学、APP 提示词、食物、动物、Emoji、颜文字**，排除上一包已经出现的输入词条。
- 同一个字形可能被不同语境解释；同一个词的不同语言版本可以在匹配层共享实现，但名称/字幕本地化。
- 所有技能为**设计候选，未写入你的真实项目代码**。请先把与现有游戏招式表重复的词剔除。
- 对同义/变体词建立 alias，例如 WIFI / WiFi / wifi；不能因翻译将 `妈`、`妈妈`、`尼玛` 混为同一个技能。
- 中文混合串使用最长短语优先；英文使用单词边界；颜文字精确字符串及宽窄字符归一化需要慎重，尤其空格。
- 如果一场比赛中大量技能触发，限制演出队列长度、共享弹幕/道具池，避免显卡绘制峰值回升。

## 足球、篮球共用原则

Arena 用现有表格的动作演出。足球/篮球无需给所有条目创造第三套招式代码，应把效果映射成：控球、传球、拦截、速度、必杀射门/投篮、无伤害视觉干扰；不允许「必杀技必进球」。例：`钱` 零钱雨干扰防守；`加载中` 蓄力重炮；`真` 识破假跑位；`妈妈` 保留旧有团队召唤而不是覆盖。

## 给 Claude Code 的验收要点

1. 去重后列出真正新增数量与冲突项目；不要覆盖现有实现。
2. 先做最明显的 15–25 个技能；每个至少有一个肉眼可见的独特动作和可测试的战斗结果。
3. 执行 `npm run docs:skills`，文档应从真实技能数据生成，不要把这些“候选”误写成“已实现”。
4. 跑已有测试、生产构建、浏览器实际战斗，并检查 60fps 目标下粒子/物品绘制调用。
5. 保持 Arena、Soccer、Basketball 各模式不回退。
